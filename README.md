# BezProblem — внутренняя система

Рабочая система из ТЗ: **авторизация сотрудников, роли и права доступа,
Dashboard**, плюс разделы «Сотрудники», «Филиалы», **«Клиенты», «Транспорт»,
«Регламентные работы» и «Должники»** — все они уже функционируют (список,
поиск, создание, редактирование) поверх единой схемы БД
(`backend/prisma/schema.prisma`).

Что можно делать в новых разделах:

- **Клиенты** — карточки клиентов (контакты, PESEL, документ, банковский
  счет), поиск, архивирование, просмотр привязанных ТС и задолженностей.
- **Транспорт** — карточки ТС, смена статуса (на филиале / у клиента / в
  ремонте / на ТО и т.д.), выдача ТС клиенту и приём обратно (ведется
  история выдач в `VehicleAssignment`).
- **Регламентные работы** — журнал ТО по каждому ТС (пробег, дата, стоимость,
  мастерская), с фильтром «ближайшие 7 дней» / «просроченные».
- **Должники** — задолженности клиента, статус (новая / частично оплачена /
  погашена / просрочена / взыскание), внесение платежей — статус долга
  обновляется автоматически по сумме платежей.

Каждое действие в этих разделах пишется в журнал `ActionLog` (см. «Журнал
действий» ниже).

## Структура проекта

```
bezproblem/
  backend/     Node.js + Express + Prisma (API)
  frontend/    React + Vite + Tailwind (интерфейс)
```

## Технологии и почему они выбраны

- **Backend:** Node.js + Express + Prisma ORM. Prisma дает типобезопасную
  схему БД и легкие миграции — удобно для проекта, который будет расти
  разделами.
- **База данных для разработки:** SQLite (файл, без установки). Для
  продакшена — переключение на PostgreSQL меняет одну строку конфига
  (см. ниже), модели не трогаются.
- **Auth:** JWT + bcrypt для хранения паролей (по требованиям раздела 14
  ТЗ — «безопасное хранение паролей»).
- **Frontend:** React + Vite + Tailwind. Права доступа проверяются и на
  бэкенде (обязательно), и на фронтенде (для UX — прячем недоступные
  разделы меню).

## Быстрый старт (локально)

### 1. Backend

```bash
cd backend
cp .env.example .env
npm install
npx prisma migrate dev --name init   # создаст dev.db и таблицы
npm run seed                          # создаст роли + первого админа
npm run dev                           # http://localhost:4000
```

После `npm run seed` в консоли будут выведены логин/пароль администратора
(по умолчанию `admin@bezproblem.local` / `ChangeMe123!` — обязательно
смените после первого входа).

### 2. Frontend

```bash
cd frontend
npm install
npm run dev     # http://localhost:5173
```

Откройте `http://localhost:5173`, войдите под администратором.

## Права доступа и роли

Список всех возможных прав — в `backend/src/utils/permissions.js`. Роль
хранит JSON-массив ключей прав (`Role.permissions`). Два предустановленных
набора:

- **Администратор** — все права.
- **Сотрудник** — просмотр Dashboard, работа с клиентами/транспортом/
  должниками (без прав на управление сотрудниками и филиалами).

Новые роли создаются через `POST /api/employees/roles` (или в дальнейшем
через отдельный экран администрирования ролей — сейчас можно управлять
через API/Postman, UI для этого — следующий шаг).

Чтобы добавить новое право под будущий раздел: допишите ключ в
`ALL_PERMISSION_KEYS` и используйте `requirePermission(...)` в роуте.

## Журнал действий (аудит)

Каждое значимое изменение (создание/блокировка/удаление сотрудника,
и в будущем — статусы транспорта, суммы задолженностей и т.д.) пишется в
таблицу `ActionLog` через `backend/src/utils/audit.js`. Это основа для
раздела 12 ТЗ «История действий».

## Автовыход по бездействию

Реализовано на фронтенде (`frontend/src/context/useIdleLogout.js`) —
20 минут без активности мыши/клавиатуры → разлогин. Значение легко
поменять в этом файле.

## Переход на PostgreSQL (продакшн)

1. В `backend/prisma/schema.prisma` замените:
   ```
   datasource db {
     provider = "sqlite"
     url      = env("DATABASE_URL")
   }
   ```
   на:
   ```
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
2. В `.env` укажите реальную строку подключения:
   `DATABASE_URL="postgresql://user:password@host:5432/bezproblem"`
3. Выполните `npx prisma migrate deploy`.
4. Настройте регулярный бэкап БД (раздел 14 ТЗ) — если хостинг это не
   делает автоматически (например, managed Postgres на Railway/Render
   обычно включает это), настройте `pg_dump` по расписанию.

## Куда деплоить (варианты)

Простой путь без своего сервера:
- **Backend + Postgres:** Railway или Render (обе дают managed Postgres
  и деплой Node.js из Git-репозитория в несколько кликов).
- **Frontend:** Vercel или Netlify (деплой статики из `frontend/`, сборка
  командой `npm run build`).
- Не забудьте прописать `CORS_ORIGIN` на бэкенде под домен фронтенда, и
  `VITE`-прокси/переменную с адресом API на фронтенде под продакшн.

Если хотите — на следующем шаге могу подготовить конкретные конфиги под
выбранный хостинг (Railway/Render/VPS) и пройти деплой вместе с вами.
